I stopped normalizing the schema at the point where each table represents a clear, meaningful entity and its attributes are directly related to that entity. Patients, scans, reports, users, and audit logs are separated because they have different responsibilities and relationships, while fields such as modality, status, role, and sex remain as constrained text values instead of separate lookup tables. I chose not to create additional tables for these small, fixed sets of values because doing so would add unnecessary joins and complexity without providing significant benefit for this system. This keeps the schema normalized enough to avoid unnecessary duplication while remaining simple and practical for the radiology scan intake system.
