# Day 9 — Aggregates, Modifying Data, Views, Foreign Keys, Transactions & Window Functions

## 1. Aggregates

Aggregate functions perform calculations on multiple rows and return a result.

Common aggregate functions:

- `COUNT()` → counts rows
- `SUM()` → adds values
- `AVG()` → calculates the average
- `MIN()` → finds the smallest value
- `MAX()` → finds the largest value

### COUNT()

Counts the number of rows.

    SELECT COUNT(*)
    FROM a;

### SUM()

Adds values from a column.

    SELECT SUM(value)
    FROM b;

### AVG()

Calculates the average value.

    SELECT AVG(age)
    FROM a;

### MIN() and MAX()

Find the smallest and largest values.

    SELECT MIN(age), MAX(age)
    FROM a;

### GROUP BY

`GROUP BY` groups rows with the same value so aggregate functions can be calculated for each group.

    SELECT age, COUNT(*)
    FROM a
    GROUP BY age;

### HAVING

`HAVING` filters groups after `GROUP BY`.

    SELECT age, COUNT(*) AS total
    FROM a
    GROUP BY age
    HAVING COUNT(*) > 1;

### WHERE vs HAVING

- `WHERE` filters individual rows before grouping.
- `HAVING` filters groups after aggregation.

# 2. Modifying Data

Modifying data means adding, changing, or removing rows.

Main commands:

- `INSERT` → adds rows
- `UPDATE` → changes existing rows
- `DELETE` → removes rows

## INSERT

    INSERT INTO a (id, name, age)
    VALUES (1, 'John', 25);

Insert multiple rows:

    INSERT INTO a (id, name, age)
    VALUES
        (2, 'Alice', 30),
        (3, 'Bob', 28);

## UPDATE

    UPDATE a
    SET age = 26
    WHERE id = 1;

Update multiple columns:

    UPDATE a
    SET
        name = 'John Smith',
        age = 27
    WHERE id = 1;

## DELETE

    DELETE FROM a
    WHERE id = 1;

# 3. Views

A view is a saved SQL query that behaves like a virtual table. A normal view usually does not store a separate copy of the data.

## Creating a View
Example:

    CREATE VIEW adult_people AS
    SELECT id, name, age
    FROM a
    WHERE age >= 18;

Now the view can be queried like a table:

    SELECT * FROM adult_people;

## Why Use Views?

Views are useful for:

- Reusing commonly used queries
- Simplifying complex queries
- Hiding unnecessary columns
- Providing a cleaner interface to data

## Removing a View

    DROP VIEW adult_people;

# 4. Foreign Keys

A foreign key creates a relationship between two tables. It ensures that a value in one table refers to an existing row in another table.

For example, suppose table `a` contains people and table `b` contains records belonging to those people.

    CREATE TABLE a (
        id integer PRIMARY KEY,
        name text
    );

    CREATE TABLE b (
        id integer PRIMARY KEY,
        person_id integer,
        title text,
        FOREIGN KEY (person_id) REFERENCES a(id)
    );

Here:
- `a.id` is the primary key.
- `b.person_id` is the foreign key.
- `b.person_id` references `a.id`.

The relationship can be represented as:

    a.id  =  b.person_id

## Why Foreign Keys Matter

Foreign keys help maintain referential integrity. For example, if `a` contains IDs `1`, `2`, and `3`, then `b.person_id` cannot normally reference an ID that does not exist in `a`.

### Adding a Foreign Key to an Existing Table

    ALTER TABLE b
    ADD CONSTRAINT fk_person
    FOREIGN KEY (person_id)
    REFERENCES a(id);

# 5. Transactions

A transaction is a group of database operations treated as one unit. The goal is to ensure that related changes are handled together.

Main commands:

- `BEGIN` → starts a transaction
- `COMMIT` → permanently saves the changes
- `ROLLBACK` → cancels the changes

## COMMIT

    BEGIN;

    UPDATE a
    SET age = 30
    WHERE id = 1;

    COMMIT;

## ROLLBACK

    BEGIN;

    UPDATE a
    SET age = 30
    WHERE id = 1;

    ROLLBACK;

## Example

Suppose money is being transferred between two accounts.

    BEGIN;

    UPDATE a
    SET value = value - 100
    WHERE id = 1;

    UPDATE a
    SET value = value + 100
    WHERE id = 2;

    COMMIT;

Both operations should succeed together. If something fails, the transaction can be rolled back instead.

### Why Transactions Matter

Transactions help protect data when multiple related operations must succeed together.

# 6. Window Functions

A window function performs a calculation across related rows while keeping the individual rows in the result.

## GROUP BY vs Window Function

`GROUP BY` combines rows into groups and normally returns one row per group.
A window function calculates across rows but keeps each original row.

Example:

    SELECT
        name,
        age,
        AVG(age) OVER () AS average_age
    FROM a;

Each person remains as a separate row, while the overall average is shown alongside each row.

## PARTITION BY

`PARTITION BY` divides the result into groups for the window calculation.

Example:

    SELECT
        name,
        age,
        AVG(age) OVER (
            PARTITION BY age
        ) AS average_age
    FROM a;

The calculation is performed separately for each partition.

## ORDER BY in Window Functions

`ORDER BY` controls the order used by the window calculation.

Example:

    SELECT
        id,
        name,
        age,
        SUM(age) OVER (
            ORDER BY id
        ) AS running_total
    FROM a;

This creates a running total.

## Common Window Functions

### ROW_NUMBER()

Assigns a unique sequential number to each row.

    SELECT
        name,
        age,
        ROW_NUMBER() OVER (
            ORDER BY age DESC
        ) AS row_number
    FROM a;

### RANK()

Assigns rankings while giving equal values the same rank.

    SELECT
        name,
        age,
        RANK() OVER (
            ORDER BY age DESC
        ) AS ranking
    FROM a;

### SUM() OVER

Can calculate a running total.

    SELECT
        id,
        value,
        SUM(value) OVER (
            ORDER BY id
        ) AS running_total
    FROM b;

### AVG() OVER

Can calculate an average while keeping every row.

    SELECT
        name,
        age,
        AVG(age) OVER () AS average_age
    FROM a;

# 7. Important Differences

## GROUP BY vs Window Function

- `GROUP BY` : combines rows into groups. `GROUP BY` is useful for summaries.

- Window function : keeps individual rows. Window functions are useful for rankings, running totals, comparisons, and calculations across related rows.

## DELETE vs DROP

- `DELETE` : removes rows.
- `DROP TABLE` : removes the entire table.

## WHERE vs HAVING

- `WHERE` : filters rows before aggregation.
- `HAVING` : filters groups after aggregation.

## Primary Key vs Foreign Key

- Primary key : uniquely identifies a row in its own table.
- Foreign key : references a key in another table.

## COMMIT vs ROLLBACK

- `COMMIT` : permanently saves transaction changes.
- `ROLLBACK` : cancels transaction changes.
